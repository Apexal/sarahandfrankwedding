# agreements

Versioned legal agreements (Terms of Service, Privacy Policy, …) with a per-user consent trail.

- **Three models.** `Agreement` is the category (stable `key`, `required`, `requires_reacceptance`); `AgreementVersion` is an immutable snapshot of the text; `UserAgreement` is one user's acceptance of one version. Both FKs on `UserAgreement` are `PROTECT` — the consent trail can never be orphaned by deleting an agreement or version.
- **Text is never edited, only re-versioned.** The `AgreementVersion` admin makes every field read-only once saved. Changing terms means adding a version and publishing it; each `UserAgreement` keeps pointing at the exact text that user accepted. Deletion is blocked for any version that is published, current, or accepted — `Agreement.current_version` is `SET_NULL`, so deleting the current version would silently switch the gate off via a bulk update that auditlog never sees. Unpublished drafts stay disposable.
- **`version` numbers itself.** Leave it blank and `save()` assigns `max + 1` for that agreement. The `unique_version_per_agreement` constraint turns a concurrent add into an IntegrityError rather than a duplicate number.
- **Publishing is the only way to advance `current_version`** — `AgreementVersion.publish()`, or the "Publish" admin action which also stamps `published_by`. It saves through the ORM (not `.update()`) so auditlog records the change and the cache-busting receiver fires.
- **The gate is `AgreementGateMiddleware`.** It redirects any signed-in user who owes a required agreement to `agreements:pending`. Staff/superusers are exempt (a bad agreement must not lock out the people who can fix it), impersonation is exempt, and the agreements app itself is exempt — identified by URL namespace via `process_view`, not by hardcoded path, so remounting the URLconf can't deadlock the gate. HTMX requests get `HX-Redirect` instead of a 302.
- **`services.py` owns the definition of "pending"** so the middleware and the acceptance page can't disagree. `get_required_version_ids()` is cached because the gate runs on every request; `has_pending_agreements()` is the one-query hot path, `get_pending_versions()` the fuller lookup used to render. The two can still diverge if the cache names a version that no longer exists, so `pending_agreements` busts the cache when it finds nothing to render — otherwise it redirects home, the gate redirects back, and every non-staff user is stuck in a loop until the TTL expires.
- **`signals.py` busts that cache twice per write — pre-commit and again `on_commit`.** The pre-commit delete stops this worker serving its own stale value; the `on_commit` one closes the window where another worker misses the cache before COMMIT, re-reads pre-publish state, and pins it for the full hour with no further invalidation coming.
- **Only `required=True` *and* `requires_reacceptance=True` agreements gate.** Unchecking `requires_reacceptance` takes the agreement out of the gate entirely — it is not "prompt once, then never re-prompt", it is "never prompt". That AND is inherited from the app this was ported from; if first-acceptance-only is ever wanted, it needs a separate has-accepted-any-version query.
- **Client IP comes from `REMOTE_ADDR`**, which `TrustedClientIPMiddleware` has already normalized from the trusted proxy header. Don't reintroduce direct `X-Forwarded-For` parsing — it's spoofable wherever the app isn't behind such a proxy.
- **`content_markdown` renders through the `render_markdown` filter**, which escapes raw HTML *before* converting, then marks the result safe. Only Markdown's own constructs become markup, so authoring `content_markdown` (an ordinary admin permission, grantable to a non-superuser tier via `core/roles.py`) can't plant script on a page served to logged-out visitors and superusers alike. The trade: no literal HTML in agreement text. Styling comes from `.agreement-prose` in `static/css/input.css` — plain CSS, since the standalone Tailwind CLI can't resolve `@tailwindcss/typography`.
- **`agreements:current` is public** (`/agreements/<key>/`) — that's the URL for footer links to Terms or Privacy. `pending`, `history`, and `versions` are reserved keys, enforced by a validator on `Agreement.key`. `agreements:version_detail` is login-only *and* scoped to `published_at__isnull=False`: version IDs are sequential, so an unscoped lookup would let anyone read the next set of terms while it is still a draft.
